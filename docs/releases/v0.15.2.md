# v0.15.2 — A faster gateway, a lighter first page, and no hell files

This patch release is a hardening pass over the whole project: the gateway's request path does less work, the web
app loads less, slow admin queries are fixed, and the code is easier to change. **No feature, API, configuration or
behaviour changes.** It has **one migration** (`00065`), which only adds indexes. Read [Rollout](#rollout).

## Faster gateway requests

Every access check is still read live; nothing that decides who may call what is cached.

| Request | Database round trips before | After |
|---|---|---|
| `tools/call`, team gateway | 47 | 33 |
| `tools/call`, platform gateway | 40 | 31 |
| `tools/list`, team gateway | 13 | 8 |
| `tools/list`, platform gateway | 10 | 7 |

- **One read of a team gateway's team** per resolve, instead of one each for the unserved check, the selection and
  the limits.
- **The live re-check of a called tool reads that tool's row alone.** It used to load and project the gateway's
  whole selection twice per call.
- **The approval-context check is one statement.** It ran inside a three-round-trip transaction before every
  upstream exchange.
- **An API key's or service account key's gateway scope comes with the key lookup**, and `last_used_at` is not
  written again when the row just read already shows a use within the minute.
- **Auth providers are read only when a selected capability can require one.**
- **Curated tools are projected once.** Projecting a curated tool compiles every property schema of its definition;
  that ran for every curated tool on every selection read. The result is now kept under a hash of the definition and
  the policy (so it can never be stale) in a 32 MiB bounded cache. For a gateway of 200 tools with 40 curated,
  evaluating the selection went from 57 ms and 10.7 MB of allocations to 3.5 ms and 1.3 MB.

## A lighter web app

- **Compressed.** The embedded app's JavaScript, CSS and other text files are served gzipped to browsers that accept
  it. A cold load transfers about 270 kB instead of about 970 kB. Nothing in front of the portal needs to compress.
- **Revalidated.** Files without a content hash in their name (the color-mode script the page waits for, icons) get
  an `ETag` and are answered `304` when unchanged, instead of being downloaded on every page load.
- **A smaller entry chunk.** The notification bell no longer pulls the list-page components into it: 54.7 kB to
  37.9 kB gzip.
- **Tabs on demand.** The server and gateway record pages load their Settings and Capabilities tabs when opened. The
  server record chunk went from 35 kB to 19 kB gzip.
- **Fewer requests.** Admin pages share one team-options request, and the review badge is fresh for a minute instead
  of refetching on every navigation.

## Admin pages and background jobs

- **Audit log.** The page is chosen before actor, team and target names are resolved for it. On a 200,000-row log a
  first page could take 3.5 s once PostgreSQL moved the statement to a generic plan; the same query now takes
  milliseconds.
- **Notification purge.** The foreign key from the delivery queue to notification events had no index, so purging
  old events scanned the queue once per event: 17 s for a batch of 1,000 on 180,000 queued rows, 9 ms with the index.
- **Call log by outcome.** Filtering the call log by a failing outcome read every call. A partial index covers the
  outcomes other than `ok`.
- **Overview.** The failed-email check the admin overview polls every minute uses a partial index.
- **Scan findings.** A server's scan-findings page reads its scans in two statements instead of two per capability.

## Code health

None of this changes behaviour.

- **No hell files.** The largest hand-written Go source file was 1,654 lines; none is now over 600, and no test file
  is over 1,000. Declarations were moved byte for byte.
- **No hell functions at the top.** 43 functions had a cyclomatic complexity over 30, the worst at 100; 23 remain,
  the worst at 67. Twenty-two functions were split into named steps without reordering a check, a lock, a statement
  or an audit write, among them the declarative planner, server create and update, upstream OAuth planning, the
  provider credential runtime and callback, and the database role inspection.
- **Guards, so it stays that way.** `make lint` (and CI) now runs `staticcheck` (72 findings fixed, 0 left) and
  `scripts/check-go-quality.py`, which holds files to those limits and functions to a complexity of 30, with a list
  of the functions still over it that can only shrink. In `web/`, `check:size` also limits line length.
- **Budgets and benchmarks.** `TestMCPQueryBudget` pins the database statements one gateway request makes, so the
  numbers above can only change on purpose. Benchmarks cover selection evaluation, list rendering and an upstream
  call. `npm run report:bundle` prints the web app's critical-path sizes.
- **Dead code removed:** unused functions in seven packages and two unused web modules.

## Rollout

- **Migration `00065`** creates three indexes with `CREATE INDEX CONCURRENTLY`, outside a transaction, and removes an
  interrupted invalid build first, so it is safe to rerun. It changes no table, function or grant. v0.15.1 replicas
  run unchanged against the new schema, and rolling back to v0.15.1 after migrating needs nothing.
- **Nothing to configure.** No new settings, no API change, no change to audit streaming gates.
- **Reverse proxies.** Responses for the app's static files now carry `Vary: Accept-Encoding` and, when gzipped,
  `Content-Encoding: gzip`. API, MCP and streaming responses are unchanged and not compressed.

## Not in this release

- **Reusing upstream connections between calls.** Every call to an MCP server still opens its own connection, so a
  TLS handshake per call. Sharing connections is likely the largest remaining latency win, but it changes the
  address-pinning and identity-isolation design, so it is an open decision, not part of a refactor.
- **The call-log purge** still scans the call log on a partial batch; the fix restates a security-definer function
  and needs its own review.
- The remaining functions over the complexity limit (JSON Schema validation, the definition scanner, approvals).

Tracked as #105 (upstream connection reuse), #106 (call-log purge) and #107 (provider token refresh holds a pooled
connection during the outbound call).

### How the pass was measured

The baseline is `main` at `1ba4bed` (v0.15.1 plus the #96 test fix), measured in its own worktree.

| Measure | Baseline | v0.15.2 |
|---|---|---|
| Database statements, `tools/call` (team / platform gateway) | 47 / 40 | 33 / 31 |
| Database statements, `tools/list` (team / platform gateway) | 13 / 10 | 8 / 7 |
| Selection evaluation, 200 tools with 40 curated | 57 ms, 10.7 MB | 3.5 ms, 1.3 MB |
| Web cold load transferred | about 970 kB | about 270 kB |
| Web entry chunk, gzip | 54.7 kB | 37.9 kB |
| Largest hand-written Go source file | 1,654 lines | 600 or fewer |
| Functions with cyclomatic complexity over 30 (worst) | 43 (100) | 23 (67) |
| `staticcheck` findings | 72 | 0 |

- **Statements** are counted by a query tracer on the test pool (`TestMCPQueryBudget`), which requires an exact
  match, so a regression or an unrecorded improvement both fail.
- **File moves** were made with an AST tool and checked by comparing the multiset of lines before and after.
- **Function splits** were reviewed diff by diff for the order of checks, locks, statements and audit writes. Two
  new tests pin behaviour the splits could have changed: the precedence of service-connection refusals and the audit
  sink change plan.
- **The approval-context change** keeps the transactional path for callers that pass a check; a new test covers the
  single-statement path, including the credential check after the read.
