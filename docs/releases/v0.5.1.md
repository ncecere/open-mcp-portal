# Open MCP Portal v0.5.1

Provider-refresh reliability follow-up to [v0.5.0](v0.5.0.md). No new feature, API operation, configuration
setting or database migration is introduced.

## Changes

- Provider refreshes use their existing transaction for endpoint dependency reads, preserving refresh-token
  serialization without recursively acquiring another runtime-pool connection. Shared and personal refresh,
  rejection retry, scope narrowing and linked-provider checks use the same bounded path.
- Address-policy checks still run before requests and at dialing. Scoped policy-read failures refuse the
  exchange; transaction reads never populate the shared network-policy cache. Linked provider state and
  endpoint matching are checked before attaching client credentials.
- The endpoint deadline includes dependency lookup, URL validation and the HTTP exchange. Serialized read
  scopes retain their original cancellation even if an HTTP dial detaches its context; closing the scope
  cancels/drains reads before transaction SQL resumes. Late reads cannot use the transaction or fall back
  to the pool.
- Failed local reads roll back without destroying an existing connection. Narrowed personal tokens enter
  the cache only after a successful refresh commit.

## Upgrade

Use the new binary or image. The schema remains at migration `00042`, so no migration is added by this patch.
The v0.5.0 tag and image remain immutable. For upgrades from v0.4.x or earlier, follow the
[v0.5.0 rollout instructions](v0.5.0.md): older images do not enforce approval rules even though their schema
remains compatible. Keep production autovacuum enabled.

## Verification and limits

The regression uses an authenticated one-connection runtime pool and two cold handlers, covering both a
single call and eight simultaneous calls. Its pre-fix failure is bounded to five seconds; the successful path
requires every call to receive a credential, exactly one actual refresh and committed token rotation.
Separate negative controls require policy denial or missing settings to prevent both refresh and credential
dispatch without erasing the grant. Linked-provider, SQL-error, cancellation/late-read and cache-isolation
regressions accompany the fix. Final CI, deployment and artifact outcomes are recorded in [status](../status.md).

Approval policy and the browser UI are unchanged. This release does not establish real-provider/IDE
acceptance, a load benchmark, a wall-clock refresh soak or a team pilot, and does not imply a production
deployment. Development stops after the verified release for the owner's machine transfer; #32 is not started.
