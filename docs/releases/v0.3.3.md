# Open MCP Portal v0.3.3

Tool-policy foundations and browser-session hardening. Migrations `00027` and `00028` are additive;
existing credentials keep their access, existing tools remain unclassified and idle expiry defaults off.

## What changed

- **Owner-set tool classification (#28).** Server team owners/admins classify tools as read, write or
  destructive, individually or in an atomic bulk edit. Upstream annotations only suggest a class; they
  never set it automatically. Changed definitions keep the owner class and show a differing-suggestion
  warning; disappeared tools lose it. Lowering a class under `approval_required` returns the server to
  review. Gateway lists overlay read-only/destructive hints from the owner class without rewriting the
  stored definition. Identity tokens and call records optionally carry the class.
- **Browser sessions (#37).** Account › Sessions lists browser sign-ins, marks the current session and
  supports revoking one or signing out everywhere, optionally keeping the current one. Platform admins
  can list/revoke a person's sessions; auditors and automation tokens cannot. Revocation cancels pending
  connect flows and is audited transactionally, without revoking apps, API keys or provider connections.
- **Optional idle expiry.** `SESSION_IDLE_TIMEOUT=0` preserves existing behavior. When enabled it accepts
  5 minutes through `SESSION_TTL`; activity is written at most once a minute across replicas, and all
  browser authentication paths and cleanup enforce expiry.
- **Concurrency safeguards.** Capability changes invalidate stale classification edits. Logout and
  session revocation use one database lock order. Session revocation UI success handling uses the
  submitted keep-current choice rather than mutable form state.

- **Patched build/test dependencies.** The Go toolchain and pinned builder image use Go 1.26.10
  (including the x509 certificate-distrust fix); the web lockfile updates Undici to 8.12.3. Release CI's
  dependency gates detected the older versions, and the gates were kept enabled.

- **Kubernetes smoke recovery.** Port-forward restart now owns and reaps the actual `kubectl` process,
  and eviction recovery waits for the evicted pod to disappear before reconnecting. A deterministic helper
  regression is run in CI; this fixes false recovery results from an orphaned forward into a draining pod.

## Upgrading

1. Apply `00027_tool_classification` and `00028_session_activity` using the normal migration step. The
   previous release remains compatible with the expanded schema; do not downgrade the schema to roll
   back the image.
2. Open reviews need one reload: the review digest is now `omp-review-v4` and includes tool classes.
3. Idle expiry is opt-in. Existing sessions receive an activity timestamp at migration without changing
   their absolute expiry. Finish rolling out new replicas before relying on idle expiry, because old
   replicas do not enforce it or update activity. Recorded activity has one-minute granularity.
4. Classification alone does not impose read-only credentials or approval requirements; scoped
   credentials (#29), curation (#30) and sensitive-call approvals (#31) follow separately.

## Verification

- Full Go suite with PostgreSQL required, generation, lint and build; focused race-enabled tests.
- 697 web tests in 71 files, typecheck, production build, styling and source-size checks.
- Desktop browser smoke tests on a disposable database: bulk/individual classification, lowering and
  re-review, read-only admin classes, existing session surviving the schema upgrade, session listing,
  remote revocation, keep-current, default sign-out and admin self-revocation. Signed-out requests
  returned 401. Checked screens had no axe violations; incomplete contrast/focus checks remain.
- A coordinated regression reproduces the old logout/revocation deadlock and passes ten race-enabled
  repetitions with the fix. Delayed-response UI tests cover revocation effects and credential clearing.

Release CI additionally runs the repository's generated-code, deployment, dependency and Docker gates.
Its outcome is recorded by GitHub Actions; preparing these notes does not itself assert CI success.

## Known limitations

Owner classification is an assertion, not verification of a tool's real effects. Very large session
inventories have not been load-tested. No wall-clock idle-expiry soak, full mobile/all-page browser pass,
real provider/client/pilot validation or live Pi Durable Platform run was performed for this batch.
Existing upstream-auth limitations remain; see [v0.3.2](v0.3.2.md).
