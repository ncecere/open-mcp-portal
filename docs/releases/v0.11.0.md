# v0.11.0 — Credential hardening and automation foundations

**Candidate, not tagged or published.** This minor release combines browser-bound personal credential hardening found while preparing #36, the #71 shared secret-rule foundation and the GitHub Action slice of #47. The hardening was initially drafted as v0.10.2; no v0.10.2 tag or release was created. It implements no SCIM functionality or new lifecycle policy. v1.0.0 remains the owner's explicit decision.

## Changes

- **API-key creation:** after waiting for the user's row lock, recheck that the user is still active before checking gateway scope or inserting a key. A request authenticated before suspension cannot mint a new key merely because it later obtains the row lock. Refusal creates no key or successful creation audit.
- **Personal connection callbacks:** after the provider exchange and any existing-connection row wait, revalidate the original user and browser session before storing/replacing tokens, consuming a consent link, recording a grant or successful connection audit. Logout, suspension, session expiry or idle expiry ends the flow with the existing expired-consent result. Suspend/reactivate does not revive the old browser session.
- **Nonblocking authority locks:** connection refresh may retain its connection row through bounded provider I/O. The callback therefore waits for that row before taking user/session authority locks; those later locks use `NOWAIT`. A busy user/session requires a new consent flow instead of forming a connection-to-user/session wait cycle. No user/session authority lock is retained during provider exchange or while waiting on the existing connection.
- **No replay or restoration:** the original authorization state is consumed before exchange as before. A final refusal never restores it, resubmits the consumed code, rewrites preserved credentials or records a successful connection audit. An already existing unrevoked key/connection remains preserved through reversible suspension (decisions38/53).

This adds no migration, schema field, public API operation, token scope, credential class, remote revocation behavior or SCIM endpoint. Existing sensitive-call, task, provider-refresh, scope, origin and sealed-state contracts remain. It is not a complete directory deletion/generation protocol or proof for every final writer.

## Shared secret rules (#71)

`internal/secretrules` owns the existing capture-redaction implementation; the parent independently compared it byte-for-byte with the v0.10.1 base, apart from the package declaration. Capture retains compatibility wrappers, with unchanged patterns, sensitive keys, exact-value normalization, ordering, counts, binary handling and truncation. Existing redaction and sentinel tests were not changed.

A separate detection profile and metadata-only `Find` primitive return fixed rule IDs and saturating counts, never matched text. Initial minimum lengths and placeholder suppression are heuristics, not calibrated enforcement. There is no JSON traversal, deadline/completeness accounting, persistence, scanner policy, refresh/call hook or safety verdict. #70/#72/#73 remain separate work.

## GitHub Action slice (#47)

`integrations/github-action/` supplies a Linux composite Action over the existing token-only CLI. It deliberately pins the independently verified v0.10.1 CLI, checks its exact checksum and Sigstore identity, conditionally imports one server, tests/refreshes it, and explicitly fails or warns when approval remains pending. Publication is a request, not human approval. Unknown publication states refuse; only the declaration's referenced secret reaches the child CLI. Repeated invocations get independent private verified installations. Inputs cannot expand token scopes or write protected governance/curation/ceiling policy.

Parent review reproduced and fixed unknown-state handling, excess secret-environment forwarding and repeated-installer collisions. Eighteen contract tests passed. The production adapter and real scratch CLI also passed a certificate-verified HTTPS front, real portal handler and mandatory disposable PostgreSQL in both actual role modes under the race detector. An initial test changed a tool absent from the fake; the corrected fixture explicitly verifies the real tool exists and retains the strict changed-count assertion. The failure is preserved. Actual public v0.10.1 download/checksum/signature verification passed without owner credentials or portal operations.

CI now runs the Action contract target and checks its shell harness. This is not execution of the composite itself in a hosted runner. Separate Action repository/publication, hosted-composite acceptance, Terraform resources/state tests, any separately reviewed delete scope and vendor registration remain unfinished; this slice does not close #47.
