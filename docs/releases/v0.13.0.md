**Published 2026-11-01T13:58:46Z; image and six CLI artifacts independently verified.** [GitHub Release](https://github.com/ncecere/open-mcp-portal/releases/tag/v0.13.0). Image index `sha256:29259a050743d6e34eb0ceefd8e1f925da140277bc07e4877add500a1ba5e2eb`, source `957d922d8ef9be114abc9a97dfbf5f22cc13b47c` (annotated tag `b850a2415c46a6fe6bb0c7902ce77a4c05b307bd`). This minor release adds approved-capability catalog search (a slice of #49) and a list-page column fix, two pieces of unwired groundwork for audit streaming (#38) and content scanning (#70), and the week's dependency updates. **It has no migrations:** the schema stays at `00056`, so upgrading from v0.12.0 changes nothing in the database.

## Catalog search (#49 slice)

- **Search what servers offer.** The catalog's search box (`GET /v1/catalog/servers?q=`) now also matches the names, titles and descriptions of a server's **approved, listed** tools, resources, resource templates and prompts, as well as the server's name, slug, team and description. Capabilities that are unapproved, changed since approval or gone never match, and fields that exist only in a definition are not searched.
- **Literal matching.** `%`, `_` and `\` are matched as typed, and Unicode is matched as given. The list returns servers only, never matching snippets.
- **Bad input is refused.** Search text that isn't valid UTF-8, contains NUL or exceeds the byte bound gets `400 invalid_search` before it reaches PostgreSQL.
- **No new access.** Search keeps the catalog's existing visibility and session-only access and grants no invocation authority. The rest of #49 (categories, tags, icons, README, verified badge, popularity) is not part of this release.

## List columns follow window resizing

On every list page, columns that are hidden by default on a phone now hide and come back as the window crosses phone width, not only at first load. Before, a desktop window shrunk to phone width left wide columns scrolling under the sticky actions column. A column someone picks in the Columns menu is still remembered (per browser) and wins at any width. A search that matches nothing in the catalog shows the table's "No results for “…”" message.

## Groundwork (unwired)

- **Audit evidence format (#38).** `internal/auditevidence` adds an experimental closed export record, a fixed binary canonical form, a versioned SHA-256 hash chain, bounded NDJSON/CSV streaming, and an incremental verifier that needs trusted start and end anchors. An independent Python reference verifier and synthetic vectors check it. **Nothing calls it yet:** there is no audit sink, sender, API, migration or retention interlock, and the record format is not final. See [audit-streaming-foundation.md](../audit-streaming-foundation.md).
- **Scanning corpus and benchmarks (#70).** `internal/scancorpus` adds an original, runtime-generated secret corpus for every current shared rule, a pinned known-miss ledger, pathological-input and count-cap cases, primitive benchmarks, and a downloader limited to one reviewed MIT public sample, pinned by revision and SHA-256. A weekly and manual `scanning-corpus` workflow runs it and uploads only aggregate numbers. **It adds no scanner, finding or enforcement**, and zero findings never means safe. See [content scanning](../content-scanning.md).

## Evidence

### Implementation proof

- **Catalog search:** integration tests cover visibility (private, disabled, archived, unapproved, changed, gone), definition-only fields, literal wildcards, Unicode, keyset pagination and the `400 invalid_search` boundaries. The authorization matrix keeps search session-only.
- **List columns:** a new UI test shrinks a desktop window to phone width and back, and checks that a saved choice survives resizing and reloads. The resize case fails on the previous template.
- **Real browser (strict):** a build of this branch, served by a restricted runtime role against an owned schema-56 fixture, passed the catalog browser check in three consecutive runs. That covers 16 search API checks, plus desktop, phone-after-resize and empty-state views with zero accessibility violations, zero incompletes and no overflow. The earlier mobile "incomplete" came from the resize case fixed here; no assertion was relaxed. One expected-text assertion was corrected to the message users actually see.
- **Groundwork packages:** unit, property and fuzz tests; the #38 Python reference verifier. For #70, the offline downloader refusal tests and an independent re-check of the pinned public file hashes and MIT licence.
