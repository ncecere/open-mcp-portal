# Open MCP Portal v0.7.0

Per-server quotas, replica-local concurrency, bounded trusted-read retries and circuit breaking: the first
stage of #33, decision84. **Multiple endpoints/failover are not included; #33 stays open for that separate
change.** These controls narrow availability, not credentials or authority. v1.0.0 remains the owner's decision.

## What changed

- **Shared server quota.** Nullable `rateLimitPerMinute` applies to a registered server across gateways,
  callers, credentials and replicas. Each forwarded tool/prompt/resource operation iteration, including an
  automatic retry, charges the PostgreSQL `v:<server UUID>` bucket. Health, discovery and negotiation are
  not separately charged. Existing person/credential/account/gateway quotas still count the inbound request
  once. Server override → owning-team override → platform default, always capped by the platform ceiling.
  Defaults/ceilings start unlimited. Values are 1–1,000,000 or null (inherit). Lower ceilings cap stored values
  without rewriting them; Admin › Limits reports capped servers. Shared remaining capacity is never exposed.
- **Fail-fast concurrency.** Nullable `maxConcurrent` allows 1–10,000 active forwarded operations per server
  **and replica**, otherwise unlimited. There is no queue. The local lease spans negotiation, retries,
  response processing and session cleanup, and releases on success, cancellation and failure. The fleet
  cap grows approximately with replica count; this is not a cross-replica lease guarantee.
- **Operational ownership.** Only the server team's owners/admins change these settings through audited,
  revision-checked server mutations. Editors can still edit permitted metadata without sending operational
  fields. Automation tokens gain no owner capability, and platform staff retain read-only access to another
  team's settings. Operational changes alone do not trigger catalog re-review or widen credential scopes.
- **Trusted-read retries.** Only owner-stored read-class tools, `prompts/get` and `resources/read` can opt in.
  At most two retries fit within the original server timeout and caller deadline, with cancellation-aware
  jitter and valid short `Retry-After` up to two seconds. Eligible failures are explicit 502/503/504, a valid
  short-delay 429, or known pre-request dial/TLS failure. A 503 is **not proof nothing executed**; repeatability
  rests on trusted classification. Never automatically replay governed/NoReplay calls, write/destructive/
  unclassified tools, continuations, progress/streamed/partial results, ordinary RPC/tool errors, auth
  rejection, local policy/admission failure or an ambiguous post-send transport failure. An annotation is
  not authority. Existing bounded OAuth renewal remains a separate path.
- **Circuit breaking.** Registered servers have replica-local protection: five failed forwarded operations,
  30 seconds open, then one half-open operation. Healthy answers recover it. Local refusals and cancellation
  do not manufacture upstream failures; a responding auth/429 server is reachable. The controller is bounded
  to 4,096 entries and never evicts active leases/probes/unexpired open circuits. Generation fencing prevents
  a late completion closing a newer circuit. `omp_server_circuit_state` uses bounded server labels, omits
  overflow instead of merging incompatible states, and retires deleted series.
- **Safe admission and records.** Fresh authority/deadlines and quota precede each forward iteration.
  Initial quota/cap/breaker refusal occurs before approval spending and downstream SSE commitment; no database
  lease or authority lock crosses upstream I/O. A spent approval is never restored. Local failures cannot
  masquerade as upstream credential rejection. One logical call record/capture remains; later retry refusal
  preserves earlier dispatch metadata, while cancellation before dispatch does not claim a prepared identity
  was sent. Server quota/cap refusal is HTTP429 with `Retry-After` and the era-appropriate RPC code
  (`-32029` legacy, `429` modern); open circuit is `-32010`, `data.reason: circuit_open`, without contact.

## Upgrade and rollback

1. Back up the database and its matching encryption/pepper/signing material consistently. Do not reset/reseed
   an existing instance, regenerate keys for encrypted records or apply development fixtures to it.
2. Apply new expand-only migration **`00046_server_protection.sql`** through the owner migration step. The
   two nullable checked columns preserve existing rows. No endpoint table, credential format, application
   dependency or new environment variable is introduced. Serving replicas keep only the restricted runtime
   URL; do not provide owner credentials to bypass startup checks.
3. **Finish rollout and drain all older serving/background-worker replicas before relying on enforcement.**
   v0.6.0 can read/write the expanded schema but cannot enforce the new quota/concurrency/retry/breaker policy.
   Schema compatibility is not policy compatibility. Existing quota/concurrency values remain null, while
   the new replica-local breaker applies to registered forwarded operations.
4. Review server/team/platform quota settings and replica count deliberately. Fixed minute windows and the
   existing UNLOGGED PostgreSQL rate store retain their burst/crash-counter limitations. Circuit/concurrency
   state is in memory and replicas briefly disagree; this is not distributed load balancing or a soak claim.
5. Keep the previous [v0.6.0](v0.6.0.md) expiry/request rollout and [v0.5.0](v0.5.0.md) approval requirements,
   including production autovacuum, live deadline checks and committed-spend semantics.

Do not downgrade the schema for an image rollback. Restoring an older image removes these enforcement
features: pause affected execution or provide equivalent protection explicitly rather than silently relying
on settings the image ignores. Preserve history and matching keys.

## Verification and remaining scope

The complete mandatory-PostgreSQL normal/race suites passed in both actual legacy and authenticated
split-role modes with `GOFLAGS='-p=2'` (2,781 seconds). Focused races cover owner/token/ceiling/audit boundaries,
shared quota across independent gateways/replicas and server isolation, approval left unspent by refusal,
revocation between read attempts, controller/probe/generation/cleanup behavior and metrics retirement.
An existing cancellation-before-transport assertion caught a prepared-identity metadata regression; the
assertion was retained and the corrected path passed, with a new no-contact cancellation regression.
Generation/freshness, lint/build, **848 web tests**, typecheck/build/styling/size and deployment checks passed.
Vulnerability checks found no reachable/imported-package vulnerabilities (two module-only advisories) and
npm audit found none. Final release-source CI/publication evidence belongs in [status](../status.md).

Chromium156 on an owned disposable schema46/restricted-runtime fixture exercised owner edits/null clearing,
editor/foreign-admin read-only controls, forward/reverse keyboard focus and modern MCP quota 200/200/429 before
SSE. Four desktop/390px states had zero axe violations/incompletes and no overflow. This is not whole-product
accessibility acceptance; prior modal/mobile-settings incomplete checks remain outside this tested scope.

The actual immutable published v0.6.0 image ran read-only as `65532:65532`, with a genuinely authenticated
restricted runtime login, no owner/migration URL and no mounts, against schema46. Doctor reported the newer
schema informationally; health/readiness, an HTTP metadata write, journal advancement and preservation of
both new settings passed. This proves expand compatibility, **not enforcement of the new controls**.

Failover still needs mode-by-mode support/refusal, new-origin credential re-entry and review, actual-endpoint
identity audiences, origin-aware era caching and all destination/provider-refresh/approval safeguards. No
production deployment, real IDE/provider/channel/pilot acceptance, broad load/soak or independent whole-product
security review is claimed. These evidence-gated issues remain open.
